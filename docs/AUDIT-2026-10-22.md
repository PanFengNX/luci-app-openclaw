## 二、发现的问题（按严重程度）

### P1 · 备份列表在含空格的安装目录下完全失效（已复现）

`backup.sh:441`

```sh
for f in $(ls -1t "$dir"/openclaw-backup-*.tar.gz 2>/dev/null); do
```

`$(...)` 的结果会被按 IFS 分词。安装目录一旦含空格，每个文件路径被拆成多段，
`[ -f "$f" ] || continue` 全部跳过 → 列表返回 `[]`。

**为什么能真实触发**：`oc_validate_base_dir` 实测**放行**含空格的路径
（`/mnt/My Disk/OpenClaw` → PASS）。而 `backup_dir()` 直接来自 `oc_base_dir()`。

**实测证据**（用真实 `cmd_list` 函数体）：

```
无空格  目录=backups        → 列出 2 个备份
含空格  目录=My Backups     → 列出 0 个备份   []
```

用户看到的是"备份页一片空白"，但磁盘上备份确实存在 —— 会让人误以为备份没成功。
清理逻辑（`cloud.sh` 的 `br_prune`）走的是远端列表 + awk，不受影响。

**修法**：不要用 `ls` 的分词结果做循环。改成 `find ... | while read -r`，或者
把 `ls` 换成带 `-1` 的 glob（`for f in "$dir"/openclaw-backup-*.tar.gz`，
无匹配时判断 `[ -f "$f" ]`）。后者更简单且 busybox 兼容。

### P1 · `api_apply` 缺 `is_post()` 强制，API Key 可经 GET 落进访问日志

`openclaw.lua:394`

```lua
function api_apply()
	local key  = http.formvalue("apikey") or ""
```

同一文件里 12 处写操作端点都有 `if not is_post() then ... return end`，
而 `api_apply` 是**唯一**一个读了密钥却没做这个检查的。

`http.formvalue()` 同时接受 POST body 和 URL query。所以
`GET /cgi-bin/luci/admin/services/openclaw/api/apply?provider=x&apikey=sk-...`
是能生效的，而 uhttpd 默认把完整查询串写进访问日志。

**这是本文件里明确写过的约定被漏掉一处** —— 注释里自己写着
「授权码与口令只从 POST body 取，绝不拼进 URL 查询串，否则会被 uhttpd 的
访问日志完整记录」，但 `api_apply` 没落实。

**修法**：在函数开头加 `if not is_post() then out({ok=false,error="请使用 POST 提交"}); return end`。

### P2 · provider id 含空格时模型页列表被拆碎

`models.sh:532`

```sh
for id in $all; do
```

`$all` 来自 `configured_list` + `preset_ids`，未加引号，按空白分词。
`openclaw.json` 里的 provider key 若含空格（JSON 允许），会被拆成多个 id：

```
$ printf 'my provider\nokone\n' | (read ...)
  id=[my]
  id=[provider]
  id=[okone]
```

实测 `catalog` 输出仍是合法 JSON，但会多出 `my` / `provider` 两个不存在的
服务商，真正的 `my provider` 反而丢失 —— 下拉框里出现幽灵条目。

**影响面比 P1 小**：官方 provider id 都是无空格的，只有用户手工编辑
`openclaw.json` 才会遇到。而 `api_apply` 侧有 `PROVIDER_ID` 形状校验
（`^[A-Za-z0-9][A-Za-z0-9_.-]*$`），所以前端本来就无法保存含空格的 id。

**修法**：`configured_providers` 的输出在进入 `$all` 前用 `grep -E '^[A-Za-z0-9][A-Za-z0-9_.-]*$'`
过滤，与控制器侧的 `PROVIDER_ID` 同口径。

### P2 · 备份下载整份读进内存，无体积上限

`openclaw.lua:1001`

```lua
local data = fh:read("*a") or ""
```

备份默认**包含 workspace**，体积可达数十到数百 MB。整份读进 Lua 内存再
`http.write(data)`，在 128MB / 256MB 内存的路由器上会直接 OOM，且 uhttpd 一并承担峰值。

**同一文件里的 `api_export` 已经是正确写法**（`EXPORT_CHUNK = 65536` 分块，
注释写着「整份 read("*a") 会把包同时压在 Lua 与 uhttpd 的内存里」）——
两个端点用了不一致的策略，`api_backup_download` 漏了。

**修法**：照 `api_export` 改成 64KB 分块循环写出。

## 四、观察项（不改，仅记录）

1. **`path-validate.sh` 未覆盖空格路径** —— 这是 P1 得以存在的原因。
   建议补一条断言：`/mnt/My Disk/OpenClaw` 应 PASS，且 `backup list` 在该目录下能列出文件。
2. **临时文件名用 `math.random` 但从未 `math.randomseed`** —— Lua 5.1 默认固定种子，
   序列可预测。**实际不构成风险**：文件名都在 0700 root 目录内，非 root 无法预置文件。
   若将来 RUNDIR 落在非 root 可写位置，这条就会变成真问题。
3. **`dist-web/` 里提交了 1.6.0 的构建产物**（544KB，含 apk/ipk/run）。
   已在 `.gitignore` 排除 `dist/` 但没排 `dist-web/`。建议加进去并 `git rm --cached`。
4. **`api/backup_log` 是死端点**（控制器有、前端从不调用）。审计工具已标记。
   要么接进 UI，要么删掉。

## 五、建议的修复顺序

1. `api_apply` 加 `is_post()` —— 一行，风险最低，收益最大
2. `backup.sh` 的 `ls` 循环 —— 三行，修掉用户可见故障
3. 备份下载改分块 —— 照 `api_export` 抄，约 10 行
4. `configured_providers` 加 id 形状过滤 —— 一行
5. 补 `path-validate.sh` 的空格路径断言 —— 防止回归

前 4 条都不改变任何对外契约，可以合并为一个补丁；第 5 条是防回归。

## 六、审计方法说明

- **实测优先**：P1 的两条都是先构造最小复现（真函数体 + 假环境）跑出错误结果，
  才写进报告；不是"读起来像有问题"。
- **提取函数用括号配对**，不用非贪婪正则 —— 中途用 `(?ms)^fn\(\)\{.*?\n\}` 
  提取 `oc_json_str` 时只截到第一个 `}`，导致 awk 报 `unterminated regexp`，
  一度误判为"转义函数坏了"。这是提取工具的错，不是代码的错，已在第三节纠正。
- **MSYS 环境的干扰已排除**：`catalog` 在本机跑不动是因为 MSYS fork/exec 极慢
  （实测 20 次 `awk` 启动 17.8 秒），与代码无关。真正验证 P2 时改用
  `read` 循环直接观察分词行为。
