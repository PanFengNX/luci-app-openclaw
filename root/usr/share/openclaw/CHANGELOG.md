### 修复：升级后备份设置被清回默认值

安装包里**直接带着 `root/etc/config/openclaw`**，包管理器把它当普通文件解压覆盖 ——

- `postinst` 与 `.run` 安装器只在 `[ ! -f /etc/config/openclaw ]` 时从模板复制，

- 新增键的默认值仍由 `uci-defaults/99-openclaw` 逐键补齐（键不存在才写）。

回归 `tools/tests/config-preserve.sh`（8 项）：断言源码树里没有该文件，并真实执行
postinst 那段逻辑，验证"已有配置逐字节不变""缺失时从模板生成""模板缺失时安静跳过"。
已接入 `verify-project.sh` 第 7g 段。

## 1.8.8

安装目录下拉里不该出现的东西。

## 1.8.7

上一版留下的四个问题。

### 版本升级：改成点选，Node 也能拉到了

- **升级框从手填改成下拉**：列表拉得到时，两行都是「点选版本」（当前版本带
  `（当前）` 标记，新版本在前；Node 第一项是「自动（推荐）」）；列表拉不到才
  退回手填框 —— 手填只作为兜底，因为写错的版本号只会在下载阶段报错。
- **Node 版本列表也能拉了。** 我上一版说"npmmirror 只镜 glibc、不能给 musl 用"，
  **这是错的**：npmmirror 确实镜像了 `node-unofficial-builds`，带 musl 构建。
  现在官方源不通时回退到它，并且**记住哪个基址能用** —— 列表与 tarball 下载
  共用同一个基址，不会出现"列表能拉、点升级却下载失败"。
  用户显式设了 `main.node_mirror` 时不自动兜底，如实报错。
- 两个源都失败时，错误里同时给出两个 URL 各自的原因。

### 模型页：下拉里的乱码

真机上模型下拉出现 `/usr/libexec/openclaw/models.sh:`、`27:`、`found`、
`timeout:` 这类"模型"。根因是**把 stderr 当成了数据**：

- `models.sh` 的 `oc_run` 用裸 `timeout`，而这台设备的 busybox 没有这个命令，
  `timeout: not found` 被 `2>&1` 合并进 stdout；
- 下游的 `grep -o` 又把报错文字按词切开，于是每个词都成了一个"模型 id"。

改法：`oc_run` 改用 `oc_timeout`（缺失时告警到 stderr 并直接执行）；
新增 `oc_run_q`（丢弃 stderr），凡是解析输出的一律用它；再加一层形状过滤
（模型 id 全小写、不含路径片段、不以冒号结尾、剔除表头词）。

「当前生效」也修了：它原来跑 `openclaw models current`，而部分 OpenClaw 版本
没有这个子命令，页面显示的是一整段报错。现在走后端新端点 `model_current`，
直接读 `openclaw.json` 的 `agents.defaults.model.primary`，不启动 CLI。

### 备份与恢复：进入页面自动检查组件更新

组件装好且可执行时，进页面自动查一次官方 CDN 上的最新版本（只读探测，不下载）。
检查期间药丸显示「检查中…」；有更新就变成「可更新到 vX.Y.Z」并把按钮改成
「更新到 vX.Y.Z」；失败只在药丸处写「无法检查更新」，不往错误区写红字 ——
自动检查不该在用户还没动手时就报错。

### 命令行：白名单扩充

新增 `providers`、`tools`、`mcp`、`devices`，以及 `--version` / `--help`。
判断标准仍是「能不能借它把任意命令塞进 shell」——这些都不能，参数照旧逐 token
过 `q()` 转义。

## 1.8.6

迁移改成「选文件夹」，版本检查改成真的能用，外加一轮排版细修。

### 迁移：目录浏览器

- 源目录不再靠手打绝对路径。新增只读的 `browse` 子命令与 `api/browse` 端点：
  只列子目录、跳过隐藏目录、按名字排序、上限 300 条，每个条目带布局类型
  （本插件 / iStoreOS 管理器 / 仅数据），`/proc /sys /dev /run` 直接拒绝。
- 页面上是「源目录 + 浏览…」，点进去逐级选择，`↑ 上一级`回退，
  `选择这个目录`落值；自动检测到的安装仍可一键「选择」。
- 目录名里的空格、中文、引号都能正确显示（走 `oc_json_str` 转义，
  含控制字符的整条跳过 —— 一个点不进去的路径比少一条更糟）。

### 版本升级：为什么之前一定失败

- **后端最坏 150 秒，前端只有 20 秒**：npm 源 60 秒 + Node 索引 90 秒，
  而状态页的 `get()` 固定 20 秒超时 —— 必然报「服务无响应」。现在单次下载
  上限 20 秒，整条链最坏 60 秒，前端按调用给 90 秒。
- **npm 取数绕过了代理**：那段是裸 `curl`，不读 `main.http_proxy`，
  只能通过代理上网的设备永远拉不到。现在统一走 `oc_fetch`。
- **官方源不通时自动回退国内镜像**（`registry.npmmirror.com`，只回退一次，
  不写回用户设置），并在页面上标明「版本列表来自国内镜像」。
  Node 不做镜像回退：musl 的 Node 只有 unofficial-builds 提供，
  拿 glibc 的版本号填 musl 机器的下拉框，选中后下载必然失败，比拉不到更糟。
- 两个源都失败时，错误里同时给出两个 URL 各自的原因。
- **进入状态页即自动检查更新**（带 `refresh=1` 绕过后端 60 秒失败缓存），
  等待期间显示「正在检查更新…」并禁用「重试」，不再让人以为这块坏了。

### 排版

- 运行环境的「Node 安装模式」单独占一行，不再挤在 Node.js 那一格里折成窄条。
- 版本升级两行改成四列定宽（标签 / 版本药丸 / 输入框 / 按钮），左右都对齐。
- 去掉状态页页脚两个重复的导航链接。
- 强调色改成与主题一致的蓝（侧栏选中项 `#6271dd` 的同色相深一档 `#5563d2`，
  保证白底仍有 5.1:1 的对比度）。

## 1.8.5

真机反馈的两处故障，加上一次界面重做。

### 修复

- **迁移不再误报「服务无响应」。** 后台子 shell 没有重定向自己的 stdio，继承了
  LuCI 请求的 stdout 管道；`io.popen` 的 close 会等到**所有**写端关闭才返回，
  而迁移要复制整个安装目录，于是请求一直挂到浏览器超时，前端报「服务无响应 /
  源目录未被改动」——**实际上后台已经在复制了**。现在三处后台启动
  （迁移 / 诊断 / 安装）都把子 shell 的 stdio 接到 `/dev/null`，请求立即返回；
  超时提示也改成「迁移可能已在后台开始，请刷新确认，不要重复点击」。
- **百度网盘登录可用。** 新版 `bdpan` 在非交互环境下要求显式
  `--accept-disclaimer`，否则 `login` 直接失败。改为**先读 `login -h` 的用法再决定
  是否传该参数**（只看行首 token，不在整行里搜子串——报错文案本身就含这个参数名），
  老版本不认该参数时自动去掉重试一次。错误信息里会去掉几十行 usage，只留真正原因。
  页面上也写明了「点按钮即表示接受百度网盘的免责声明」。

### 界面

- **重做共享样式表**（10 个视图逐字节一致）。真机上键值单元格被
  `minmax(200px)` 自动填充成四列，每个值只剩约 40px，版本号被折成一字一行；
  若干行是裸 div，按钮/输入框/复选框自由流动，「上传并恢复」被挤到单独一行。
- 现在：键值行是「定宽标签 + 紧跟其后的值」两列网格（每列不足 340px 就单列，
  长值不再被撕碎）；表单行标签 116px，控件按类型限宽，提示强制换行到控件下方；
  `time` / `number` / `file` / `checkbox` 补上样式；分组标题带短竖条；
  行内按钮与操作条里第二个之后的按钮自动降为次要样式，一屏不再有五六个同权重
  的实心蓝按钮；说明卡片改成列表。
- 明暗两套主题、940px 与 865px 两种卡片宽度都渲染核对过，并用 DOM 探针检查
  「内容比容器宽」的元素：无。

## 1.8.4

本版全部来自两轮安全审计（一轮针对源码、一轮针对 1.8.3 的安装包），没有新功能。

### 安全

- **网关不再可能以 root 运行。** 原先只有 `openclaw` 用户存在时才会设置 procd 的
  运行用户，用户缺失（创建失败、overlay 写满、被手工删除）时这条设置被整条跳过，
  网关会**以 root 启动并监听局域网**，而日志里只有一行正常的 `started`。
  现在用户不存在就拒绝启动；属主修正失败会记警告，不再静默吞掉。
- **网盘组件安装器加入校验锚点。** 下载后只记录 sha256、不做比对就执行的路径已关闭：
  官方 3.7.3 / 3.7.1（arm64 与 amd64）的 sha256 已实测并写入代码，不匹配拒绝执行；
  未收录的版本仍会执行，但日志明确写「未校验」。安装器地址强制 https。
- **Node.js 下载改为 fail-closed。** 原先校验清单拉不到、清单里没有该文件、
  系统缺少 `sha256sum` 三种情况都会静默放行。现在一律中止，只保留一个显式开关
  `main.allow_unverified_node=1`，打开时会记录跳过了什么。
- **可执行文件不再走明文 http。** `oc_safe_url` 的注释声称阻止明文降级，实现却放行。
  现分两档：默认仍允许 http（内网镜像需要），下载 Node.js 运行时这类可执行文件走
  strict 只接受 https；确需明文可设 `main.allow_http_binaries=1`，并会告警。
- **网关 token 不再随每次页面加载返回。** 状态接口只给掩码（`****abcd`），
  完整值改由单独的 POST 接口按需获取，且响应禁止缓存。
- **登录状态判定改为「必须有正面证据」。** 结构化输出不再走文本兜底 ——
  原先 `{"error":"invalid username or password"}` 会被判成「已登录」。
- **加密备份的 auth tag 回填改为原子操作**（先写 `.tmp`，回填后改名），
  中途断电不会留下无法解密的文件；口令临时文件改用 `mktemp`。

### 修复

- **crontab 备份文件移出 `/etc/crontabs/`。** busybox crond 把该目录下每个文件名
  当作用户名加载，`root.openclaw.bak` 会被当成一个用户，轻则刷日志、重则备份每天跑两遍。
- **定时任务的脚本路径不再写死。** 非标准安装位置下 cron 行指向不存在的脚本，
  cron 静默失败，用户以为备份在跑；现在会回退到脚本实际目录，不可执行则拒绝写入。
- **远端轮转不再误删最新备份。** 原先缺失 mtime 会被当成「最旧」而优先删除，
  epoch 与 ISO 混排时顺序完全错乱；现在统一归一化成秒级时间戳，解析不了的行不参与删除。
- **日志加上限**（256KB 保留一代），避免 tmpfs 被日志吃满。
- **版本号校验收紧**：必须数字开头且不含 `..`（会被拼进下载 URL）。
- **错误信息按行截断**，不再把中文切成半个字符导致前端解析失败。
- **wget / uclient-fetch 现在也会走代理**（此前只有 curl 走）。
- **安装脚本结尾校验可执行位**：`chmod` 静默失败时让包管理器报安装失败，
  而不是装完提示「命令不存在」。

## 1.8.3

- **迁移改成下拉选择。** 自动检测到的旧安装直接列在下拉里（路径 + 布局类型 +

  蓝色竖条、表单改为「左标签 + 右控件」并支持窄屏堆叠、按钮统一为实心强调色

### 修复

- **没登录却显示「已登录」。** 登录判定原先以「`bdpan whoami` 退出码为 0」作为
  已登录的兜底依据，而该命令在未登录时同样返回 0，只是输出「未登录」。现在
  **必须有正面证据**（明确的布尔字段、非空的账号字段、或明确的「已登录」文本）
  才判定为已登录，其余一律按未登录处理并记录原因；页面对「无法确认」单独提示。
- **「从 OpenClaw 刷新列表」点了没有结果。** 该接口服务端最多等 20 秒，而上一版
  给所有请求统一设了 20 秒客户端超时，客户端总是先放弃。现按接口区分超时
  （此接口 60 秒），并区分「超时」与「没有模型」两种失败原因。
- **自定义服务商不再出现「安装插件」。** 自定义服务商没有配套插件，按钮改为
  「保存 Key 并设为默认」，并说明只保存地址、Key 与默认模型。

## 1.8.2

### 新增

- **安装网盘组件时能看到进度了。** 下载 14 MB 安装器、校验、运行安装器原先全在
  一个请求里完成，页面上只有一个秒表。现在日志会逐行出现：
  `开始下载` → `已下载 3.2 MB / 13.4 MB`（每秒刷新）→ `下载完成，校验文件` →
  `校验通过，运行安装器` → `安装完成`。
- **迁移改为后台执行。** 迁移要复制整个程序目录与工作区，几十秒到几分钟，
  原先跑在请求里，超时后页面只会显示"服务无响应"。现在后台执行、页面显示已用时，
  超过 30 分钟或连续查询失败才停止，并提示"迁移可能仍在后台继续"。
- **迁移支持手动指定目录。** 自动检测只扫固定名字的候选目录，扫不到时页面上
  什么都没有。现在可以随时填写旧安装的绝对路径直接迁移。
- **模型清单改为实时获取。** 已填 API Key 时向服务商上游查询；未填时查询公开模型
  目录（无需鉴权，也不携带任何凭据）；两者都失败才使用内置清单，并在页面上注明
  「当前显示内置清单，可能不是最新」。清单来源会在页面上标明。

### 修复

- **网盘组件仍然装不上。** 上一版虽然不再依赖 `od`，但调用安装器时传的是
  `--install-dir`，而这个安装器是 Go 程序，只认 `-dir`，于是它直接以
  `flag provided but not defined` 退出。现在改为**先读安装器的帮助信息探测它认哪些
  参数**（`-dir` / `-install-dir`、`-yes` / `-y`），认不出目录参数就中止并回显帮助，
  绝不退回"裸调用"——那会把组件装到默认位置，破坏"更新只动组件目录"的约定。
- **安装日志长时间不动。** 心跳从 30 秒改为 15 秒，下载阶段额外显示已下载字节数，
  能区分"慢"和"卡住"。
- **界面请求没有超时。** 备份、安装、设置、状态四个页面都写了超时处理，
  却没有设置超时时间（默认 0 = 永不超时），那些处理是死代码。一次请求挂住就会让
  轮询静默停住、按钮永久禁用。现在按用途分级：状态与轮询 20 秒，备份/恢复/安装等
  15 分钟，归档上传 30 分钟。

## 1.8.1

### 修复

- **网盘组件在部分设备上永远装不上。** 下载完成后要用 `od` 读文件头判断是不是 ELF
  可执行文件，而部分 OpenWrt / iStoreOS 的 busybox 没有编进 `od`：命令不存在时输出为空，
  错误又被丢弃，于是魔数永远是空值，任何下载都被判成「不是 ELF 可执行文件」。
  现在改用 `head` / `tail` 取文件头，不再依赖 `od`；架构校验在 `od` 缺失时跳过
  （架构不符的二进制执行时内核本来就会拒绝）。报错信息同时带上文件体积与前 4 个字节，
  下次出问题能直接看出拿到的是不是 HTML 错误页。
- **安装目录下拉里只有系统分区。** 候选目录原来按挂载点名字匹配，挑中的
  `/tmp`、`/overlay`、`/mnt`(tmpfs) 恰恰都是安装校验明确拒绝的目录，而真正的数据盘
  反而不在列表里 —— 从下拉里选任何一个都必然安装失败。现在只列真实可写磁盘
  （ext4 / f2fs / xfs / btrfs / exfat / vfat / ntfs 等），排除只读挂载与系统分区，
  并让每个候选都通过安装时那套目录校验，按可用空间从大到小排列。
- **设置页的二级菜单出现两次。** LuCI 会根据菜单定义自动渲染一遍，页面上又硬画了一排
  同样的按钮。已删除手写的那排。
- **GLM 模型列表停留在 5.1。** 未保存 API Key 时下拉使用的是内置清单，而这份清单没跟上
  Z.AI 的更新。现补齐到 5.3 家族（`glm-5.3` / `-flash` / `-flashx` / `-prime`，以及 `5.2`），
  默认模型改为 `glm-5.3`。
