# 更新日志

版本按倒序排列，最新的在最上面。

## 1.8.28

按实际运行日志与代码复核后的一批修复：

**会坏 / 会丢数据**
- 覆盖安装前先停服务，收尾用 `restart`（`start` 对运行中的实例是空操作）。
  直接在运行中的网关脚下替换 `node_modules` 会让新版本不生效、也可能导致段错误。
- 云端备份的暂存目录从 `/tmp`（tmpfs）改到数据盘，并用硬链接树代替整份
  `cp -a`。这台机器数据 7.8G、tmpfs 仅 4.2G 可用 —— 原来的配置下备份**每天必失败**。
- 还原不再把备份里的 `/etc/config/openclaw` 整份写回：只搬端口 / 绑定 / 镜像源 /
  云备份计划等非路径项，路径类保留本机值（否则属主修复会对着错路径白做）。
- 还原改为「起服务并等到端口应答才算成功，失败自动回滚到还原前数据」，
  不再先删旧数据再起服务。
- 卸载改用专用端点并检查返回值：原来前端发的是后端白名单里没有的
  `cmd=uninstall`，必失败却无条件报「已提交」，而且先把服务停了。
- 15 个写端点在入口层统一要求 POST（此前 GET 就能触发还原 / 装包）。

**等待与性能**
- 「服务启动成功」统一改为等进程 + 等端口应答，上限 120 秒（原来 15 秒，
  而这台机器冷启动实测 28 秒）。
- 状态页进页面不再强制联网刷新版本列表（原来一次加载最多占住 CGI 80 秒）。
- 版本缓存 TTL 真正生效（原来只看文件非空，列表永不过期）。
- 版本号优先读 `package.json`，不再每次轮询都起一个完整 Node 进程。
- `start` 时若顶层属主已正确就跳过 `chown -R`（`$home` 下 7.8G，几十秒）。
- 进程终止改为 TERM → 等 30 秒 → KILL，并确认清空后才删程序目录。

**安全**
- 去掉 `models.sh` 里「SecretRef 失败就明文写 apiKey」的回退：那会把密钥放进
  进程参数。位置参数传 key 也一并拒绝，只保留 `--key-file` 与环境变量。
- rpcd ACL 去掉 `/etc/config/openclaw` 的裸 write 授权（本包写操作都走 cli.sh，
  且该授权能绕过全部路径校验）。

**其它**
- 备份排除规则改为精确路径：原来 `--exclude='logs'` 会匹配任意层级，
  连 `workspace/logs` 这类用户数据一起排除（已实测复现）。
- 日志与诊断命令保留真实退出码：原来 `| tail` 让 `$?` 恒为 0，失败显示成功。
- 备份页的超时不再被无条件覆盖（`x.timeout = 20000` 把 900 秒覆盖掉）。
- 安装日志保留上一份（`.1`），不再每次清空。
- `uci-defaults` 判空改为「键不存在」才写默认值，避免升级重跑时覆盖用户清空的值。

## 1.8.27

- **按钮点下去有反应了**：启动 / 停止 / 重启 / 刷新此前只发一个请求再静默等待，

  但界面从未读取。状态页新增「启动日志」面板，点「启动 / 重启」自动展开并轮询；
  日志页新增来源切换（管理脚本 / 网关输出 / 全部）。
- 日志页读取失败时不再显示「(无日志)」—— 那是把"请求失败"伪装成"没有日志"。
- doctor 体检按钮加了忙态，期间禁用并显示「体检中…」。

## 1.8.26

继续审计，又发现三处：

- **「服务在跑吗」用了模糊匹配**：`pgrep -f 'openclaw.*(gateway|run)'` 会把终端页的
  `cli.sh run date` 和用户的 `tail -f ...openclaw.log gateway` 都判成网关在运行，
  于是状态页谎报「运行中」、`--force` 不触发。改用 `oc_gateway_pids` 比对 argv。
- **`.run` 安装漏了 `rpcd reload`**：`postinst` 有，但 `.run` 是独立脚本，
  装完新 ACL 不生效（表现为接口 403）。已补齐。
- **README 的历史版本号被升版时的盲替换改错**：「迁移功能 1.8.16 移除」被改成了
  「1.8.25 移除」。已恢复并加注。

审计规则也补了一条：`pgrep -f` 不只禁止用来强杀，**做存在性判定同样禁止**。

## 1.8.25

深度审计后的修复：

- 未安装 / 已停止时不再探测网关端口（原来每次白等 1-3 秒，结论无意义）。
- 「端口未应答」的提示此前被 `renderOpen()` 覆盖、永远看不到；现在提示只有一个来源，
  按「端口无效 > 端口未应答 > 服务未启动」的优先级显示。
- 触摸设备放大复选框时误伤了滑块开关的内部 input（同特异度、后定义者赢），
  改为 `.oc-row>` 子选择器，不依赖 Selectors Level 4。
- `collectEnvPayload()` 返回值改为结构体，不再往表单数据里塞 `__install` / `__nm`
  再让调用方 `delete`（漏删会把 `[object Object]` 发给服务端）。
- `install.sh` 把 xz 当硬前提（缺了直接给出 `opkg install xz-utils` 提示），
  不再只 warn 然后以「解压失败（tar）」收场；`repair.sh` 也一并检查 xz。
