# 更新日志

本文件记录 luci-app-openclaw 的版本变更，格式参考 Keep a Changelog。
版本按倒序排列，最新的在最上面。

## 1.8.1

### 修复

- **网盘组件在部分设备上永远装不上。** 下载完成后要用 `od` 读文件头判断是不是 ELF
  可执行文件，而部分 OpenWrt / iStoreOS 的 busybox 没有编进 `od`：命令不存在时输出为空，
  错误又被丢弃，于是魔数永远是空值，任何下载都被判成「不是 ELF 可执行文件」。
  现在改用 `head` / `tail` 取文件头，不再依赖 `od`；架构校验在 `od` 缺失时跳过
  （架构不符的二进制执行时内核本来就会拒绝）。报错信息同时带上文件体积与前 4 个字节，
  下次出问题能直接看出拿到的是不是 HTML 错误页。
- **安装目录下拉里只有系统分区。** 候选目录原来按挂载点名字匹配，挑中的
  `/tmp`、`/overlay`、`/mnt`(tmpfs) 恰恰都是安装校验明确拒绝的目录，而真正的数据盘
  反而不在列表里 —— 从下拉里选任何一个都必然安装失败。现在只列真实可写磁盘
  （ext4 / f2fs / xfs / btrfs / exfat / vfat / ntfs 等），排除只读挂载与系统分区，
  并让每个候选都通过安装时那套目录校验，按可用空间从大到小排列。
- **设置页的二级菜单出现两次。** LuCI 会根据菜单定义自动渲染一遍，页面上又硬画了一排
  同样的按钮。已删除手写的那排。
- **GLM 模型列表停留在 5.1。** 未保存 API Key 时下拉使用的是内置清单，而这份清单没跟上
  Z.AI 的更新。现补齐到 5.3 家族（`glm-5.3` / `-flash` / `-flashx` / `-prime`，以及 `5.2`），
  默认模型改为 `glm-5.3`。

## 1.8.0

### 新增

- 云备份的引导卡片接通了。1.7.0 只有后端命令，页面上没有入口；现在「备份与恢复」页
  按三步走：安装网盘组件（显示架构与已装版本、约 14 MB，用已用时长而不是假进度条，
  因为后端调用不是流式的）→ 登录百度账号（新标签页打开授权链接，同时把链接放进只读
  输入框方便复制，再填授权码）→ 备份/恢复。
- 组件更新：显示已装版本，「检查更新」探测官方 CDN，「更新组件」安装探测到的版本或
  手填版本。官方**没有**版本清单接口（`latest` 系列全部 404），所以检查只能逐个探测候选
  版本并取最高的；全部探测失败时明说「下载源不可达」，不会假装「已是最新」。
- 定时备份界面：周期、时间、保留份数可设并写入 crontab，页面显示后端报告的实际 crontab 行，
  不在前端拼装。组件缺失或未登录时允许保存定时设置，但页面会提示定时执行会失败——
  写入定时和能不能跑是两件事。
- 加密改为显式开关（`cloud_encrypt`，默认关）：开启且已设口令才加密；开启但无口令
  直接报错，**不会**静默降级为明文上传。关闭时即使口令仍在磁盘上，也按明文上传，界面同步说明。

### 变更

- 组件目录分层：`<安装目录>/cloud/bin`（安装器目标，更新时整体替换）、
  `cloud/home`（网盘组件的 HOME，存登录态，更新不写）、`cloud/pass`（口令）。
  此前 HOME 在安装目录**里面**，重装组件可能把登录态一起冲掉。

### 修复

- `cloud.sh` 里 **17 个函数被定义了两次**：两个批次各写了一整套定时 / crontab /
  备份执行逻辑，后一份静默覆盖前一份。shell 不会因此报错，但生效的那份丢了
  「重写 crontab 后其他定时任务的行数不变」这道校验——没有它，`crontab -` 往返
  把别人的定时任务截断了，也照样显示成功。已删除弱实现，并用真实 crontab 夹具回归：
  他人的行字节不变、我们恰好一行、二次执行幂等、清空后他人的行完好。

## 1.7.0

### 新增

- 百度网盘云备份：在「备份与恢复」页按三步引导完成 —— 安装网盘组件（按架构自动下载
  arm64 / amd64 静态二进制）、登录百度账号（获取授权链接 → 粘贴授权码）、
  手动或定时备份到网盘并可从云端恢复。
- 云端备份加密：可设置口令，上传前用 AES-256-GCM 加密（口令只保存在本机，不上传）；
  恢复加密备份时需要输入口令。
- 定时备份：可设每天/每周、具体时间、保留份数；只清理符合命名规则的备份文件。
- 设置下新增「更新说明」页，展示本文件的内容。

### 变更

- 下线「关联已有安装」，只保留「迁移」：统一在本插件自己的目录下运行，避免两套目录
  共用同一份配置导致行为不一致。
- 备份与恢复仍为顶层菜单，不放在「设置」子菜单里。

### 修复

- `state_dir` 被覆盖时，CLI 与网关会读写不同目录里的配置与 `.env`（表现为改了模型/
  端口不生效、API Key 写了仍报未配置）。现在由 lib.sh 统一导出
  `OPENCLAW_STATE_DIR` / `OPENCLAW_CONFIG_PATH`，init 脚本也按 state_dir 推导。
- init 脚本对 state_dir 的递归 chown 增加了符号链接与系统路径校验。
